# Zilux2 需求分析表

> 版本：1.2.11 · 编制日期：2026-11-24 · 适用形态：Windows 桌面端（WPF 宿主 + WebView2 界面）
>
> 用法：`优先级` 列可自行改为 P0/P1/P2；`状态` 列填「已实现 / 部分实现 / 规划中」；`验收标准` 是可直接复现的观察点，不是形容词。

## 一、产品定位与核心差异

一句话定位：**不绑定单一平台、以「自动 DJ 式过渡 + 分轨人声分离」为核心能力的本地优先音乐播放器。**

| 维度 | Zilux2 | QQ 音乐 / 网易云音乐 | 差异说明 |
| --- | --- | --- | --- |
| 曲库来源 | 多平台聚合（网易云 / QQ / 酷狗 / 私有源）+ 本地曲库 | 单一平台自有版权库 | 曲库不绑死一家，本地与在线混排在同一队列 |
| 过渡方式 | 自动分析拍格/调性/能量/人声/结构后规划过渡（16 种手法），支持变速对齐、低频交接、人声让位、A 尾自延长 | 淡入淡出 / 交叉淡化 | 过渡是「编曲级」的，不是固定曲线 |
| 分轨能力 | HTDemucs 人声分离，实时切换人声/伴奏，可做清唱叠加 | 部分曲目提供伴奏，不可离线、不可分轨控制 | 分轨是本地算力，模型按需下载 |
| 歌词 | 逐行 + 逐词扫光、封面歌词、桌面歌词（含粉丝向样式）、AMLL 歌词 | 逐行歌词 | 歌词是渲染管线的一部分，可做视觉演出 |
| 桌面融合 | 动态壁纸层（视频/网页/着色器）、桌面图标下铺桌面层、系统音频 OSD、全局热键、托盘 | 无桌面层能力 | 播放器与桌面环境打通 |
| 可扩展性 | 本地 HTTP API（分析特征、分轨模型、壁纸媒资）+ 页面级调试钩子 | 封闭客户端 | 便于脚本化、二次开发与自动化测试 |
| 体积 | 安装包约 21 MB，人声分离模型按需下载 | 安装包 100 MB+ | 首装轻，能力按需加载 |

**结论（最大优势）**：把「多平台曲库」与「DJ 级自动过渡 + 分轨」合到一个客户端里，且过渡与分轨都在本地完成——QQ 音乐/网易云的优势在版权与推荐，Zilux2 的优势在**播放过程中的二次创作能力**与**不被单一平台绑定**。

## 四、约束与假设

- 目标平台为 Windows 桌面；移动端只提供遥控页面，不提供独立客户端。
- 在线曲目受第三方平台接口约束，接口变更可能导致某个源短时不可用，需可降级。
- 人声分离依赖本地算力，CPU 版 ONNX Runtime（1.31.1）为基准；DirectML 1.24.x 会触发 DFT 属性冲突，禁止回退。
- 动态壁纸与桌面层依赖 DWM/WebView2 的合成行为，部分全屏独占程序下会暂停。
