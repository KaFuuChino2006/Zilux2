# Zilux2 v1.2.0

这一版把「下一首什么时候进」从一刀切的等功率叠化升级成真正的 DJ 式过渡：新写的进阶混音 v2 会先把低频让开、再按乐句边界换手、需要时做双向扫频，还能事前判断这一接会不会轰、会不会咬字；同时把界面骨架换成一套统一的运动系统——每个内容块自己挑一款动作、自己的时间出发，出场沿原轨迹倒着退回去、随时可打断。围绕这套骨架，加了第二套「FX」界面模板、封面内嵌歌词、换新样子的悬浮导航条（带一次性引导）、边听边拆的实时分轨试听，以及全屏应用自动让位、真屏扫光、ALAC / DSF 直读这些细节。

## 新功能

- **进阶混音 v2**：新的「进阶混音（智能选点）」模式，做三件标准路径做不到的事——低频换手（两首的底鼓/贝斯在 60–120 Hz 高度相关，等功率叠加会在交叠中点凭空 +3 dB，所以低频单独走一条先降后升的曲线）、分段等功率（不同频段不同交叉点，不整轨一起淡）、双向扫频（A 收低通、B 起高通，交叠区不堆能量）。它与标准路径完全隔离，切回标准就是原样，连节点都不共用。
- **过渡形态选择**：按「最像 DJ」到「最保守」五种形态——重复 A 的尾段乐句把过渡补到 B 的乐句边界、变速对齐 + 频段换手 + 扫频、把 B 的 drop 对齐 A 的 drop（只混两小节）、短等功率交叉、直接切；选哪种由曲风、能量、唱词活动度与两侧小节线共同决定。
- **过渡风格目录与质量门**：每种风格直接标出它要占用哪些 DSP 原语（频段换手 / 双扫 / 人声闪避 / 混响送出），按可用原语打分选型。质量门四项指标全部在规划期算完（低频叠加峰值、人声重叠拍数等），不合格就事前换一个保守形态——一次过渡只有十几秒，播放中改曲线会被听出来。
- **结构桥接**：需要重复 A 的尾段时，把那一小段 PCM 预渲染成 buffer 用第三路 source 播，不在元素上回跳 `currentTime`（seek 回来有 20–40 ms 空洞，120 Hz 刷新下就是一声「噗」）。只缓存真正要用的 8–16 秒尾段，不把整首解成 PCM。
- **离线移调**：把下一首的前奏移几个半音去贴上一首的调，再当桥段用。走颗粒合成 + 互相关对齐（SOLA），只改音高不改速度，过渡前算一次，不参与实时渲染。
- **实时分轨试听**：分轨监听改成连续跟播，不再是「抓 30 秒离线放一遍」。按 30 秒滚动窗口 + 提前预取（宿主分离一段实测 6.7–7.6 秒，算 7 秒能放 30 秒），每 350 ms 检查一次，剩余不足 20 秒就把下一窗口按元素时间轴折算成 context 时间接上去。混音浮层底部可以直接听四轨。
- **混音实时浮层**：开发者选项里的透明面板，把一次过渡里所有会动的量摊开——每帧只读一份纯数据快照改文本与宽度，不碰任何 AudioParam，看到的曲线就是听到的那条；面板可以拖，位置至少留 120×60 在视口内，永远抓得回来。
- **FX 界面模板**：设置 → 通用 → 界面 → 界面模板新增 `standard` / `fx` 两套。FX 只保留底部播放条，今日推荐改成「整块封面渐变 + 正方形卡片网格」的舞台，左侧大封面里跟着唱封面歌词。两套界面共用同一个 App 实例与同一份播放器，来回切换不打断正在播放的歌、不重载音频；FX 的新样式全部写在 `.app.is-fx` 下，切回标准永远原样。
- **封面歌词**：点右侧卡片或封面本身开始播放后，封面里只露三句——上一句缩小退后、正在唱的放大并带一层白色辉光、下一句略小略淡；换行时三句真的往上滚一格，元素相互挤压让位，不是原地换字。
- **逐块运动引擎**：首页、海报墙、发现页、动态壁纸页共用一套——每张卡/每行/每个区块标题自己挑一款变体（11 种内容款 + 6 种标题款）、自己的随机时间出发，出场用同一款的反向关键帧沿原轨迹退回去；打新一段之前先把上一段的类摘干净并强制回流，不会出现「点了没反应」或只播半截。
- **页面标题逐字入场**：标题不再整块淡入，每个字自己往上飘 12px、从 4px 模糊里显影，逐字错帧（34 ms + 最多 18 ms 抖动），读起来是一行字依次落定。
- **统一运动系统**：界面上所有「换内容」的动画都从同一处发——时长、缓动、位移只认那两三组常量，每个动画都是入场 / 出场 / 打断三件套，打断永远先取消再重新发，不叠加、不排队。
- **悬浮导航条与一次性引导**：侧栏原来的左侧常驻竖排改成上方浮动胶囊——首页常驻居中，其他页面鼠标靠近才出来、停 5 秒自动收起；任意空白处右键能把它召到光标处，可以拖动、拖右下角小柄改大小、双击空白复位；打开搜索时自动让开。首次使用（或本版更新后第一次启动）会弹一次说明，把悬停、右键、拖动、让位四条讲清楚，看过记在本地，之后不再打扰。
- **全屏应用自动让位**：前台是全屏游戏或全屏视频时，桌面壁纸挂起——只暂停解码（一路 4K 视频约吃 30–40% 单核），播放位置留着，退出全屏从原处接着播，不重新拉流。
- **真屏扫光**：在画布设置里点选某块屏时，那块屏的实际壁纸自上而下扫过一道炫彩光，一眼确认选的是哪一块，而不只是弹层里高亮。
- **ALAC / DSF 直读**：本地曲库可以直接放 ALAC（m4a）与 DSF。ALAC 判定要同时看文件头尾——`moov` 按规范可以在文件末尾，只读前几 MB 会把它当成普通 `audio/mp4`，而 Chromium 没有 ALAC 解码器，结果是整首静音且没有任何提示；现在识别对了。DSF / ALAC 首次播放需要整首转码，重活丢线程池并拿 deferral，响应回来再回 UI 线程，不会让整窗未响应。
- **分析扩展**：主分析多出三路活动度曲线、调性时间线与可循环单元，全部复用已经算好的频段能量 / 谱通量 / 谱平坦度 / 逐小节 chroma，不做源分离，所以只是多算一点点。
- **所有内容页都能滚到窗口最上沿**：海报墙、歌单、全部歌曲、本地曲库、统计页与动态壁纸页都跟首页一样，内容可以顶到窗口最上边（不再被顶栏压出一条空带），搜索框与左侧 ZILUX 也跟着滚动手感走——向下滚时让开，停手约 0.9 秒自己回来，随时点得到。
- **搜索激活时导航条让位**：不分界面，只要搜索面板打开，悬浮导航条就淡出并让出点击，关闭搜索再回来；首页那条常驻的也一样。
- **分段切换统一**：所有「一排按钮选一个」的控件（播放页的启动 / 桌面歌词 / 系统、首页两组推荐标签、快捷设置等）统一成同一套观感与滑动：底部一条浅色槽、白色滑块按实测的 `offsetWidth` / `offsetLeft` 写 `left` 与 `width`（不用百分比），0.38 秒带一点回弹的位移，窗口变宽变窄与折行都会重算，`prefers-reduced-motion` 下不滑。
- **风格分类下拉自绘**：首页「风格分类」不再用系统原生 `<select>`（弹层由系统画，改不了样式），换成跟随应用主题的下拉，键盘、Esc、点外部都能关。
- **首页推荐行换标签的转场**：换「为你推荐 / 官方歌单 / 风格分类」或 QQ 那组标签时，内容不再是整块淡入淡出——旧内容每块沿自己那款反向错帧退场、新内容每块随机变体错帧入场，和切换页面是同一套引擎；异步补进来的卡片也会在数据落定时补一次入场，不会静止地凭空出现。

## 改进与修复

- **歌词页被今日推荐整页压住**：从今日推荐点进「全部歌曲」再开歌词，歌词会跑到内容后面。原因是内容层被抬到歌词之上后靠「自己隐退」露出歌词，而隐退名单里漏了今日推荐整页这一层；补进名单，并让它在淡出走完（260 ms）之后再撤可见性与点击，关闭歌词时立刻恢复。
- **开着动态壁纸时搜索框点不到、也不在最前**：壁纸层里把顶栏与内容层写成了同一个 `z-index`，DOM 里排在后面的内容层就压住了搜索框，点哪儿都落到卡片上。内容层留在 1（要压住壁纸的压暗层），顶栏回到全局的 30。
- **重复时间戳的歌词**：间奏里同一时刻挂两行、或时间轴被工具压平，会让高亮只停在最后一行、前面那行永远不亮、时长还算成 0；读入时做一次单调化（至少 +1 ms 递增，时长按下一行起点推算、最小 200 ms）。
- **歌词来源标签重复**：同一平台被拼成「QQ 音乐 · 逐字（QRC）· 匹配 100% · 逐字 QQ 音乐 · 逐字（QRC）」再被省略号切掉，同平台不再罗列一遍。
- **歌词匹配的异步覆盖**：每次开始匹配 / 手动选源 / 清空都递增一个代际号，后台结果落地前先比对，避免「匹配途中手动选了来源」又被自动结果盖回去。
- **画布状态被整行覆盖**：暂停一次壁纸就把某块屏的帧率、裁剪、转场一起写成空——画布保存改成先读现有行、只改调用方点到的字段。
- **标题条与工具条错位**：内容页上探过顶栏之后，标题条还按顶栏高度吸顶，会被滚上来的卡片压住；改成随内容一起滚走，回到顶部自然复位。

## 已知限制

- 进阶混音 v2 只在两侧都接进音频图（图模式）的过渡里生效；元素直出、没走音频图的播放仍走标准路径。
- 旧的「分轨换手」两档（进阶 / 稳妥）保留在设置里只作对照，它在播放期跑分轨，不作为推荐路径。
- 结构桥接只缓存尾段 8–16 秒；尾段特别长的曲子会被截断到可缓存长度。
- 实时分轨按 30 秒窗口提前一个窗口预取，宿主正忙或素材在网络盘上时仍可能来不及，表现为短暂回到原轨。
- FX 模板只保留底部播放条与今日推荐舞台，标准界面的部分入口（如统计、本地曲库的详情面板）仍需切回标准模板。
- 多屏壁纸仍按原始分辨率解码，4K 屏的 GPU 占用依旧明显。
- 桌面歌词窗口的 WebView2 在部分机器上只在重新显示时整体重绘，页内动画观感以最终态为准。
