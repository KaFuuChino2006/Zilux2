# Zilux2 启动崩溃：d3d9.dll（2026-11-06 21:00 之后）

## 结论（先说）

**不是 Zilux2 的代码问题，是机器当前的 WPF/D3D9 图形栈坏了。** 同一时间点，任意
WPF 程序（包括一个空的 PowerShell 窗口）启动都会在 `d3d9.dll+0x607e8` 处访问违例，
随后 CLR fast-fail（`0xC0000409` / ntdll+0x124446）。

**恢复办法：重启电脑（或注销再登录）。** 重启后先用下面的 walk-check 验证，再启动
Zilux2。

## 证据

1. 应用事件日志（Zilux2.exe，2026-11-06 21:06–21:19 每次启动）：

   ```
   出错模块名称： d3d9.dll，版本 10.0.26100.9549
   异常代码： 0xc0000005
   错误偏移： 0x00000000000607e8
   ```

   紧随其后是一条 `.NET Runtime 1026`：

   ```
   Exception Info: exception code c0000005, exception address 00007FFA39AD07E8
   ```

   （该地址反查模块 = d3d9.dll+0x607e8。`0xC0000409` 是 CLR 在渲染线程未处理异常后的
   fail-fast，不是根因。）

2. 最小复现（与 Zilux2 无关）：

   ```powershell
   Add-Type -AssemblyName PresentationFramework
   $w = New-Object System.Windows.Window
   $w.Show()
   ```

   用 Windows PowerShell 5.1 `-STA` 运行 → 进程同样以 `0xc0000005 / d3d9.dll+0x607e8`
   崩溃。说明是"这台机器现在建不了任何 WPF 窗口"，不是应用逻辑。

3. 排除项：
   - 与 stems 末窗容差改动无关（把容差改回 64 重编译发布，仍崩）。
   - 与 WebView2 用户数据目录无关（`%LOCALAPPDATA%\Zilux2\WebView2` 换新 profile 仍崩）。
   - 与单文件解包缓存无关（清空 `%TEMP%\.net\Zilux2` 仍崩）。
   - 与 WebView2 控件无关（把 `<wv2:WebView2>` 从 XAML 摘掉、禁用 `InitializeComponent()`
     后仍然崩；去掉 XAML 后崩溃点前移到 `window.Show()`）。
   - 强制 `RenderOptions.ProcessRenderMode = SoftwareOnly` 也无效（D3D9 在更底层初始化）。
   - 时间线：21:00 的构建还能正常启动并跑通尾小节事件；21:03 之后同代码开始必崩，
     期间唯一的外部动作是对运行中实例反复 `Stop-Process`/重启。推测是反复强杀让
     显示/驱动栈进入了坏状态（D3D9 设备初始化失败）。

## 重启后的验证步骤

```powershell
# 1) 先确认 WPF 能起窗口（不依赖 Zilux2）
Add-Type -AssemblyName PresentationFramework
$w = New-Object System.Windows.Window; $w.Show(); Start-Sleep 2; $w.Close()

# 2) 再启动 Zilux2（当前发布版）
& "$env:LOCALAPPDATA\Programs\Zilux2\Zilux2.exe"

# 3) 如需同步日志定位启动问题，带环境变量启动：
$env:ZILUX2_SYNC_LOG = '1'
```

`ZILUX2_SYNC_LOG=1` 会让 `HostLog` 直接同步写 `%LOCALAPPDATA%\Zilux2\logs\host.log`，
崩溃前的最后一行不会再丢（正常的异步日志队列可能丢尾部）。

如果重启后仍崩（极小概率），再依次尝试：更新/回滚显卡驱动 → 关闭「GameViewer
Virtual Display Adapter」等虚拟显示器 → 检查是否处于远程桌面会话（RDP 下 WPF 偶发
D3D9 失败）。
