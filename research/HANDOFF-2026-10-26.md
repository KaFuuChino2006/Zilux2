## 5. 高频命令速查

```bash
# 前端类型检查 / 构建（在 web/ 下）
cd E:/Zilux2开发/web
"$NODE" ./node_modules/typescript/bin/tsc --noEmit
"$NODE" ./node_modules/vite/bin/vite.js build

# 只改前端 → 直接覆盖安装目录 web
cp -rf web/dist/. "$LOCALAPPDATA/Programs/Zilux2/web/"

# 改宿主 → 构建 + 发布 + 部署 + 重启（pwsh 里 $LOCALAPPDATA 才展开）
E:/dotnet/dotnet.exe build src/Zilux2/Zilux2.csproj -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish.ps1 -SkipWebBuild
taskkill /IM Zilux2.exe /F
cp -rf dist/Zilux2/. "$LOCALAPPDATA/Programs/Zilux2/"
pwsh -Command '$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223"; Start-Process "$env:LOCALAPPDATA\Programs\Zilux2\Zilux2.exe"'

# QA（用户明确要求时才跑）
"$NODE" research/qa/suite/run-all.mjs            # 全量
"$NODE" research/qa/suite/run-all.mjs crossfade  # 单套件
```

坑位：
- `publish.ps1` 必须带 `-NoProfile -ExecutionPolicy Bypass`，否则执行策略拒绝；发布后校验产物非 NUL（`tr -d '\0' < file | wc -c`）。
- 重启应用必须用 pwsh `Start-Process`（bash 的 `start` 不可靠），并带上 CDP 环境变量。
- CDP 调试：`http://127.0.0.1:9223/json/list` 取页面；页面内 `window.__ziluxPlayer` 是**函数**，要 `window.__ziluxPlayer()` 才拿到状态；`window.__ziluxCrossfade.snapshot()` 为无缝衔接调试状态。
- 采集/诊断脚本模板在 `research/tmp/` 与 `research/promo/*.mjs`（Node 24 内置 fetch + 全局 WebSocket，无需 `ws` 依赖）。
