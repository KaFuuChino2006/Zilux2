**系统媒体键接管（第三十三轮，宿主 + 前端）**：

用户先报「软件在后台时，快捷键无法使用」，澄清后是「系统的原生切换在其他页面不生效」——Zilux2 不在前台时，键盘系统媒体键（播放 / 暂停、上一首、下一首）不控制 Zilux2；全局组合键实测正常。

- 根因（真机诊断）：宿主 SMTC 正常启用，但 `[smtc] control pressed` 停在 2026-10-20；探测程序注册媒体键 VK 0xB0 / 0xB1 / 0xB3 全部失败 `error=1408 (ERROR_HOTKEY_ALREADY_REGISTERED)` → QQ 音乐等程序用 RegisterHotKey 在系统级抢注了媒体键，SMTC 的 ButtonPressed 收不到；实测 WH_KEYBOARD_LL 钩子仍能看到这些键，且吞掉后 QQ 收不到。
- 实现：新增 `src/Zilux2/Media/MediaKeyHookService.cs`（WH_KEYBOARD_LL 媒体键钩子，仅当「快捷键总开关开启 + Zilux2 是当前媒体会话」时吞键并走同一条 `SendCommand` 命令链：0xB0→next / 0xB1→prev / 0xB3→togglePlay，0xB2 不接管；自动重复只触发一次、keyup 一并吞掉，注入按键放行）；`Interop/NativeMethods.cs` 补钩子常量 / `KbdLlHookStruct` / 委托 / P-Invoke；`Media/MediaSessionService.cs` 新增 `GlobalSystemMediaTransportControlsSessionManager` 当前会话跟踪与 `IsCurrentSession`（日志 `[smtc] current session id=… ours=…`）；`MainWindow.xaml.cs` 在 `OnSourceInitialized` 装钩子、`OnClosed` 卸载（日志 `[mediakey] hook installed`）；`web/src/ui/app.ts` 快捷键设置页补媒体键说明文案。
- 构建部署：宿主 `dotnet build -c Release` 0 警告 0 错误；`publish.ps1 -SkipWebBuild` → `dist/Zilux2/Zilux2.exe`（29,320,009 bytes）+ web payload；已复制到安装目录并重启（PID 2836）；前端 `main-Cs-uQjUv.js`（883.29 kB）/ `main-DccpaaFn.css`（232.45 kB）。针对性冒烟（媒体键链路，非完整 QA）：`[mediakey] hook installed` + `[smtc] current session id=Zilux2.exe ours=true`，注入媒体键 → `mediakey.fire action=togglePlay` → 页面暂停；同时 smtc-diag 复核 QQMusic 仍是原状态 / 原曲目（未收到媒体键）。详见 `research/UPDATES-2026-10-25.md` §39。
