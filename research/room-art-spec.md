## 2. 圆环隧道几何（核心）

### 2.1 推荐参数（与任务书假设一致）

相机：位置 `(0, H, 0)` 看向 `+z`，**水平、无俯仰、无滚转** ⇒ 视平线/画面中心 = **y 480**。
地面 `y=0`，环同心圆中心在 `(0, 0, D)`。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 画面 | 1600×960（5:3） | |
| 垂直 FOV | **50°** | `f = (H/2)/tan(25°) = 480/0.46631 =` **1029.36 px** |
| 等效水平 FOV | 75.7° | `2·atan(800/f)`；宽视角，纵深感强 |
| 相机高 H | **3.0**（世界单位） | 地面在画面下 3 个单位 |
| 环中心超前 D | **13.0** | = 4.33×相机高 |
| 灭点 / 环中心投影 | **(800, 718)** | `y = 480 + f·H/D = 480 + 1029.36·3/13 = 717.6` → **74.8%H** |
| 环带世界宽 w | **0.52**（半宽 0.26） | ≈0.37×环间距 |
| 环间距 s | **1.40 世界单位** | 由动画「spawn 周期 T=0.55s × 扩张速度 v=2.55 单位/s」实现；或按屏幕阶梯比 q≈1.42 |
| 环数（屏上可见） | **8~10** | 近环出画后回收 |
| 环色 | `rgba(252,249,245, α)` | 暖白 #FCF9F5；**不要纯白** |

屏幕公式（实现直接用这些，别用「贴图缩放」）：
```
a(半长轴) = f·R/√(D²−R²)
b(半短轴) = f·H·R/(D²−R²)      // 也就是 b/a = H/√(D²−R²)
cy(中心y) = 480 + f·H·D/(D²−R²)
yTop      = 480 + f·H/(D+R)
yBot      = 480 + f·H/(D−R)
bandMajor = a(R+w/2) − a(R−w/2)          // 环带在水平方向上的像素宽
bandVert  = f·H/(D−R−w/2) − f·H/(D−R+w/2) // 环带在中央纵线上的竖直像素宽
```
> 注意符号：屏幕 y 向下；`R→D` 时近点无穷远（环穿过相机），实现里 `depth = D − R·sinθ` 必须 `clamp ≥0.55`，且 `R ≥ D−0.35` 的环要回收。

读表要点（也是验收点）：

1. **环带宽度**：近环水平 86px、远环 **恒 ≈41px**（因为 `bandMajor → f·w/D = 1029.36×0.52/13 = 41.2`）。所以「远环细」指的是**竖直方向**：竖直环带 67 → 10.5px。别只缩 alpha 不缩竖直厚度。
2. **中心 y 全部向 718 收敛**（885 → 718.7）：环越远越贴灭点，这是纵深感的来源；**不要给远环单独平移中心**。
3. `b`（竖直半轴）从 260 → 16：近环很「扁」，远环更扁但**绝对尺寸小**；因此看起来是「地面上的隧道口」。
4. 环顶 y 从 624.6 到 702.4：**隧道最上沿 ≈605~625**，所以画面 0~600 全是「天空/空气」——歌词就放在这一带（§3.4）。
5. α 曲线：`α_k = 0.98 − 0.28·(k/(n−1))^0.85`（近 0.98 → 远 0.70）。实现里按实时半径 `u = R/D`（0 远 → 1 近）取 `α ≈ 0.68 + 0.49·u`（clamp 0.62~0.98），视觉等价。

### 2.3 动画推进（镜头前进 = 环向外扩张）

实现模型（`roomScene.drawRings` 已在用，确认过：环=地面同心圆，随时间半径增大并回收）：

```
travel += speed·dt                     // speed ≈ 2.55 世界单位/秒（1.2~3.0 可调）
T = 0.55s                              // 每 0.55s 生成一个新环
R_i(t) = ((t − i·T)·v + R0) mod (D − 0.4)   // 半径从 0 长到 D，到边回收
α_i:  入画 0→目标值用 120ms 淡入；出画（R > D−0.9）用 200ms 淡出
扰动：R_eff = R·(1 + 0.012·sin(3θ+φ1) + 0.008·sin(5θ+φ2) + 0.005·sin(9θ+φ3)) + 0.02·sin(2θ)
φ1=0.7i, φ2=1.9i+2.0, φ3=3.1i+0.4；θ 0..2π，240 段折线（每段 ≤2px 弦高即可）
```
- 相机「跟着歌词走」：每唱完一行 `camZ += LINE_GAP`（推荐 **5.6 世界单位**，见 §3.6），环的推进与相机位移**叠加**，形成持续的「向前走」而不是原地抖动。
- 情绪（energy）加成：α 乘 `(0.93 + 0.14·energy)`，环扰动幅度可乘 `(1+0.5·energy)` —— 但**别让环在屏幕上明显抖**（会晕）。
- 回收：`R > D−0.9` 时直接重置到 `R≈0.2` 并淡入，避免「环穿过相机」的巨大白块（见 §6）。

### 2.4 与 `roomScene.ts` 现有常量的换算（实现参考）

现有实现：`CAM_HEIGHT=0.9`、`RING_CENTER_DEPTH=12.6`、`FOV_Y=50°` ⇒ `f=1029.36`：
- 环中心投影 `y = 480 + f·H/D = 480 + 1029.36×0.9/12.6 =` **553.5（57.7%H）**，而目标表是 **718（74.8%H）**；
- 环扁平度 `b/a ≈ H/√(D²−R²)`，现有 `H/D = 0.071`，比参照图（0.10）更扁；
- 结论：现有参数**隧道离人太远/太靠上**，画面像「远处地板上的一圈圈」，不是参照图那种「就在脚下、正对着我们」的隧道。

## 3. 排版与逐词

### 3.1 参照图字形（对标基准）

| 项 | 参照图 | 1600×960 换算 |
| --- | --- | --- |
| ink 高度 | 47/214 = **22.0%H** | 211px（但我们的词是分散摆放，**按宽度换算更合理**） |
| ink 宽度 | 139/518 = **26.8%W**（3 字） | 单字 **≈145px**（0.96em ⇒ font-size ≈151px） |
| 字重观感 | **超粗 + 圆角**（笔画宽 ≈25~28% 字高、笔画端头圆、氵/折笔糊成一团） | 见下 |
| 字距 | pitch ≈ ink 宽 ⇒ **letter-spacing ≈ 0** | 0 ~ 0.01em |
| 颜色 | **暖白 #F7EFED**，p95 #FAF2F0 | 文字 `rgba(255,251,246, α)`；唱过/正唱 `#FFFDFA` |
| 阴影 | 参照图几乎没有阴影/描边（平贴） | 目标可加：`0 10px 34px rgba(19,83,66,.22)`（**很轻**） |

**字重实现（重要）**：项目只打包了 `Zilux2 Sans SC` **Regular(400)**（`web/public/fonts/zilux2-sans-sc-regular.ttf`），撑不起「超粗圆润」。必须：
1. `font-weight: 900`（浏览器合成加粗）；
2. **`-webkit-text-stroke: .05em currentColor`**（比现有 `.026em` 厚一倍：实测 0.05em ≈ 笔画 +30%，接近参照图；试过 .026em 仍偏细）；
3. 可选 fallback 栈把「Noto Sans CJK Black / 微软雅黑 Bold」放前面（仅 Windows 有），但**主字体必须还是打包字体**（避免加载不一致）。
   - Pillow 对照实验（`research/tmp/font-compare.png`）：`SIMYOU+stroke16/220px` 最像参照图；`Zilux2Sans+stroke13` 粗细够但转角方正。浏览器里用 900 + stroke .05em 可接近前者。
4. 圆角感没法靠 CSS 得到：**不要用 `border-radius` 这类技巧去「磨圆」文字**；接受方形转角，或用 `filter: blur(.2px)` 轻微柔化。

### 3.2 当前句字号（任务区间 110~150px，推荐 **145px**）

参照图实测单字 ink ≈145px（1600 宽换算）——参照图的字**非常大**。取 **145px** 作为 1~3 词短句的推荐值（落在任务区间 110~150 的上限附近）。词数增多必须缩小，否则逐词散开后叠满画面、压住隧道（下表的下降档位；超过 150px 绝对不要）。

| 每句词数 n | 推荐字号（中心值） | 允许范围 |
| --- | --- | --- |
| 1~3 | **145px** | 130~150 |
| 4~6 | 132px | 118~145 |
| 7~9 | 112px | 100~130 |
| 10~14 | 88px | 78~105 |

公式（与实现 `baseFrac` 对齐）：`sizePx = clamp(0.40 / n^0.62, 0.046, 0.18) × 960`，再把 n=3 的结果 172.8 手动钳到 145（**视觉上限 145~160，不要 172**，那会压住隧道）。
`room-target.png` 用的就是 **158 / 168 / 144px**（三个词分别略大/略小 ±7% 制造手摆感）。

- 字距：`letter-spacing: .005em`（≈0.7px@145px）；不要更大。
- 行高/词框：`textHeight = sizePx × 1.16`（用于避让碰撞检测）。

### 3.3 三态透明度与光晕（逐词）

| 状态 | 颜色/透明度 | 光晕 | 缩放 |
| --- | --- | --- | --- |
| 未唱 | `rgba(255,251,246,.52)` | 无（仅基础阴影） | 1.00 |
| 唱过 | `rgba(255,251,246,.92)` → 稳定后 **.88** | 弱：`0 0 10px rgba(255,255,255,.18)` | 1.00 |
| **正在唱** | `#FFFDFA`，α **1.00** | 强：`0 0 26px rgba(255,255,255,.60), 0 0 68px rgba(255,255,255,.28)` + 基础投影 | **1.03~1.05**（弹一下回落） |

基础投影（所有态）：`0 10px 34px rgba(19,83,66,.22)`。
> 已实测：投影 α 到 0.3 以上、或 offset 太大，会在薄荷绿上变成「脏灰块」（见 §6）。目标稿用的是 blur≈34px、offset 12px、alpha 0.10×字层。

### 3.4 逐词随机布局安全区（1600×960）

「一个平面空间」= 一块**始终正对相机**的虚拟平面（billboard），词在平面内随机撒开，深度用 z 表示（见 §3.5）。当前句的词**不得**进入底部条、播放条、以及太贴边。

| 约束 | 数值（words box 中心点） |
| --- | --- |
| 水平安全区 | **x ∈ [264, 1336]**（16.5%~83.5%W；= `±0.335W` from center） |
| 垂直安全区 | **y ∈ [221, 533]**（23%~55.5%H；= `-0.27H ~ +0.055H` from 480） |
| 词框半宽/半高 | `w/2 = sizePx·0.5·n`? 单字：`±0.5×(sizePx×1.0)`；避让用 `sizePx×1.16` 作框高 |
| 词间距 | 词框之间 **≥ 18px**（水平/垂直都算），允许轻微交错但**不要重叠**（重叠=不可读第一杀手） |
| 底部禁区 | y > 700 一律禁止（隧道区 + 标题胶囊 y810~868 + 播放条 854~960） |
| 贴边 | 距左右上边缘 **≥ 40px** |
| 推荐网格 | 5% 步长（x 每 80px、y 每 80px）做随机种子格，先在格内抖动 ±±12px 再碰撞检测 |

实测参照：目标稿当前句词心在 y 372/424/446，远句词心 222~258，长句 12 词在 y 236~368 —— 都在 §3.4 安全区内。

### 3.5 纵深（近/远）→ 字号、透明度、雾化

词的「深度」用相对量 `d ∈ [−1.1, +1.1]` 表示（正=更近），渲染时：
```
wordDepth = camZ − line.z            // line.z = −index × LINE_GAP
k = (FOCUS_DEPTH + d) / wordDepth    // FOCUS_DEPTH = 7.6
displaySize = sizePx · k
```

| 深度区间（当前句 wordDepth ≈ 6.5~8.7） | dispSize | 实际 α（乘状态 α 与雾） |
| --- | --- | --- |
| 近 · wordDepth 6.5~8.7 · d>0 | 125~165px | .95~1.0（几乎不透明） |
| 中 · wordDepth 8.7~12（下一句） | 92~125px | .30~.55 |
| 远 · wordDepth 12~18 | 61~92px | .14~.34 |
| 极远 · 18~34（下一句以后的 ghost） | 32~61px | .04~.14，可加 1~2px blur |

雾化：`fog = smoothstep(34, 6, wordDepth)`（远→近 0→1），最终 α = 状态α × 行α × fog。
- 行 α（多行同时可见）：当前行 1.0；下一行 `0.34·0.5^(d−1)`；上一行 `0.34·0.4^(-d-1)`，且下限 0.04（**再低就直接隐藏**，省性能也更干净）。
- 隐藏条件：`wordDepth ≤ 1.2`（飞过镜头）或 `k > 2.35`（字大得离谱）→ 直接 `visibility:hidden`。

### 3.6 行与行之间的间距（世界 z）

- `LINE_GAP = 5.6` 世界单位/行（约等于「走 1.4 个相机高度」）；`FOCUS_DEPTH = 7.6`（当前句停在相机前 7.6 单位处）。
- 相机推进：`camZ_target = line.z + FOCUS_DEPTH − 0.5·smoothstep(lineProgress)`，阻尼 `λ=3.4`（播放中）；切歌/拖动进度条时**直接跳**（λ=20），不要慢慢飞。
- 观感校验：每行之间相机前进 5.6 单位 × f/7.6² 量级的屏幕位移，约等于「词从画面下方 8~12% 高度处掠过」；如果一行歌词还没唱完就飞出画面，说明 LINE_GAP 小了。

### 3.7 动效（90° 正视约束：只能做平面内运动）

禁止：`rotateX/rotateY`、`perspective` 动画、俯仰摇晃、3D 翻转、镜面反射。
允许（推荐实现）：

1. **入场**（每词 380~520ms）：`scale: k·0.94 → k·1.0`（easeOutCubic）+ `opacity 0 → 状态α` + 屏幕空间 `y` 上浮 12px → 0 + 0.6px 模糊 → 0。按词序 **stagger 70ms**。
2. **点亮**（唱到的瞬间，220ms）：`α → 1.0`，`scale → k×1.04`，辉光两级同时到最强；随后 300ms 回落到 `k×1.0`、α 保持 1.0（正在唱）。
3. **唱过**（350ms）：辉光收到弱档，α 1.0 → .88。
4. **换句**：上一句整体 `opacity ×0.28` + `translateY(−0.5%H)` + 随相机自然缩小（由 `k` 驱动，不要额外做 UI 位移）；下一句从「远」自然放大到「中」，同样由 `k` 驱动。
5. 词的静态旋转：每词 `rotateZ ∈ ±5.4°` 固定（手摆感），**不随时间转**。
6. 所有动效都用 `transform/opacity`，不要改 `top/left/font-size`（会掉帧 + 抖动）。

## 6. 最易翻车点（按踩坑概率排序）

1. **地面出现「地平线」**：环的外面必须还是同一张薄荷渐变，**绝对不要**画一条地面/天空分界线或给地面单独换色 —— 参照图没有地平线，一画立刻变「舞台布景」，90° 正视的设定也会崩。地面 = 同一渐变，靠环的透视和雾化表达「这是地」。
2. **环太规则 → 像靶心/唱片**：纯同心圆 + 等宽 + 等透明度 = 靶盘。必须加：±1.2%/0.8%/0.5% 的正弦半径扰动（每环相位不同）、近环更粗更实/远环更细更透、环顶 y 从 625 递减到 702 的收敛。目标稿的环一律带 240 段折线 + 扰动。
3. **字太透/太细，看不清**：`Zilux2 Sans SC` 只有 400，若不加 `-webkit-text-stroke`，145px 的字会像细线；再把未唱 α 压到 .35 以下、叠上雾化，就彻底读不出。硬性下限：**未唱 α ≥ .50，stroke ≥ .05em，font-weight 900**；唱过的词不能再低于 .85。
4. **暗角过重**：α 上限 0.16（现在实现是 .42 的渐变 stop，实际落到角上 ≈.17，勉强；若再加一层黑角就脏了）。参照图本身无暗角，本项目的暗角只是「收一下四角」，不是「压黑画面」。
5. **环穿过相机**：`R > D−0.9` 的环没回收时，`D−R` 接近 0 ⇒ 坐标爆到几十万像素 ⇒ 整屏白闪/卡死。实现里 `depth < 0.55` 要 clamp，环到边要回收并淡出（已写在 §2.3）。
6. **标题胶囊在白色环带上不可读**：见 §5 的 tint + scrim，别指望 `backdrop-filter` 自己能压住白色环带。
7. **相机有俯仰/滚转**：参照图有 ≈-3.5° 滚转和轻微仰拍（是 MV 的镜头语言），**如果照抄**，环会歪、地面和歌词平面不再 90°，明确禁止。所有摄像机参数必须 pitch=0, roll=0。
8. **投影/辉光变成脏灰块**：薄荷绿是高明度背景，大 blur + 高 α 的深色投影会显灰脏。投影 α ≤ .22（<26px 小 blur 时）/ ≤ .12（>30px 大 blur 时）；正唱辉光用**白**不用绿色。
9. **颗粒/噪点过大**：2px 以上颗粒 + 低透明环 = 「旧电视」。1px、σ≈1.4% 就够；canvas 用 `devicePixelRatio` 渲染，颗粒在 CSS px 尺度上要细。
10. **每帧重算 10 环 × 240 段 + 全屏 blur** 在低端机掉帧：环用 `Path2D` 每帧重建但只画可见包围盒；收敛雾/暗角/渐变**缓存到离屏 canvas**，每帧只 `drawImage`；颗粒交给 CSS overlay（已实现），不要 canvas 逐像素生成。
