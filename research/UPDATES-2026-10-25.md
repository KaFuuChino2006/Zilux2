# Zilux2 更新记录（2026-10-25）

## 1. 本轮：后台常驻 / 托盘图标与交互 / 全局快捷键 / 下载入口迁移 / 快捷设置下载页 / 下载音质选择

用户需求（原文）：「现在给软件新增后台常驻功能，桌面任务栏小图标，与相关的点击交互，还有全局的快捷键，左侧下载图标移动到便捷设置，在便捷设施新增一个下载页面，同时，点击下载的时候可以选择下载音质」。

拆成六件事并全部落地：①关窗不退、进程常驻；②托盘小图标 + 左键/右键交互；③全局快捷键；④左侧 rail 的「下载队列」入口移除；⑤快捷设置新增「下载」页；⑥点下载时先选音质。

### 1.1 宿主（WPF/.NET 10）

- **后台常驻**：`App.xaml` 的 `ShutdownMode` 从 `OnLastWindowClose` 改为 **`OnExplicitShutdown`**，窗口隐藏后进程（播放、下载、热键、WebView2）继续存活；只有托盘菜单「退出」和更新安装两条路径会真正退出。`App.xaml.cs` 启动时创建托盘服务、退出时先撤托盘；新增 `OnSessionEnding` 兜底——Windows 关机/注销放行真正的关闭。
- **关窗即隐藏**：`MainWindow` 新增 `Closing` 处理——托盘可用时取消关闭并 `Hide()`；页面自绘关闭按钮的动画路径用 `_pendingHideToTray` 在动画结束后隐藏；Alt+F4 / WM_CLOSE 同路径。托盘不可用（初始化失败）时回退为真正关闭 + `OnClosed` 里显式 `Shutdown()`，不会留下无窗口进程。
- **托盘图标**（新增 `src/Zilux2/Tray/TrayIconService.cs`）：`System.Windows.Forms.NotifyIcon`（`Zilux2.csproj` 加 `UseWindowsForms`），图标从 exe 关联图标提取；左键单击切换显示/隐藏（400ms 防抖，避免双击触发两次）；右键菜单 = 显示主窗口 / 播放或暂停 / 上一首 / 下一首 / 退出；首次隐藏时弹一次气泡提示「Zilux2 仍在后台运行：音乐继续播放。单击托盘图标恢复窗口，右键可播放控制或退出。」；`Dispose` 幂等。
- **全局快捷键**：`MainWindow` 在 `SourceInitialized` 后 `RegisterHotKey`，`WndProc` 处理 `WM_HOTKEY`（0x0312），退出时注销。每个动作带候选回退（不同机器上 Ctrl+Alt+←/→ 常被输入法/显卡驱动占用）：

  | 动作 | 默认键 | 候选回退 |
  | --- | --- | --- |
  | 播放/暂停 | `Ctrl+Alt+Space` | — |
  | 上一首 | `Ctrl+Alt+←` | `Ctrl+Alt+Shift+←` → `Ctrl+Alt+J` |
  | 下一首 | `Ctrl+Alt+→` | `Ctrl+Alt+Shift+→` → `Ctrl+Alt+K` |
  | 显示/隐藏窗口 | `Ctrl+Alt+Z` | — |

- **命令通道**：托盘菜单与热键统一走 `MainWindow.SendCommand` → `WebViewHost.PostCommand` → 页面消息 `{v:1,type:'command',action:'togglePlay'|'prev'|'next'}`；宿主日志记录 `hotkey.register` / `hotkey.fire` / `tray.command` / `tray.hide|show|balloon` / `app.exit reason=...`。
- 新增/修改文件：`src/Zilux2/Tray/TrayIconService.cs`（新增）、`App.xaml`、`App.xaml.cs`、`MainWindow.xaml.cs`、`WebViewHost.cs`、`Interop/NativeMethods.cs`、`Zilux2.csproj`。

## 3. 快捷设置切 tab 尺寸过渡与滑块错位修复（2026-10-25 追加，未发版）

### 3.1 背景

用户反馈两点：
1. 快捷设置切 tab 时面板尺寸（宽/高）直接跳变，希望有动画过渡；
2. 动画期间「开关的显示背景」会错位或变形（分页栏白色胶囊、内容里的分段滑块停在旧位置/旧宽度）。

### 3.2 实现（`web/src/ui/app.ts`、`web/src/styles/app.css`）

- **宽度过渡**：`.quick .quick-panel` 补 `transition: width .32s cubic-bezier(.22,1.28,.36,1)`（与高度同款弹簧）；`prefers-reduced-motion` 下 `transition: none`。不同 tab 的目标宽度：封面/歌词/设置 348px、投送 384px、下载 508px。
- **高度按目标宽度预量**：新增 `measureQuickBodyHeightAtTargetWidth(fromWidth)` —— 临时加 `.is-resizing`（关宽度过渡）让布局落到新 tab 的目标宽度，量出内容自然高度，再把宽度退回旧值交给 CSS 过渡；高度动画沿用 `animateQuickBodyHeight`（`.quick-body` 的 `height` 过渡）。这样宽度过渡结束时内容重排不会再让高度跳一截。
- **宽度落定/异步内容补动画**：新增 `scheduleQuickBodySync()` / `syncQuickBodyHeight()`；`ResizeObserver` 观察 `quickBodyInner`，宽度过渡期间把高度变化攒着，落定（380ms 窗口）或异步内容（下载列表/投送设备）加载完再补一段短动画。
- **滑块跟手重排**（修「错位/变形」）：
  - 分页栏胶囊 `.quick-thumb`：新增 `paintQuickTabThumb(animate)`，并对 `.quick-tabs` 建 `ResizeObserver`，宽度过渡期间每帧以 `transition:none` 即时贴合选中按钮；
  - 内容分段滑块 `.quick-seg-thumb`（背景/歌词模式/音质/播放效果…）：新增 `repaintQuickSegThumbs()`，由 `quickBodyInner` 的 `ResizeObserver` 每帧重排；`.is-width-animating` 期间关闭补间，避免滑块滞后。
- `destroy()` 统一断开两个 `ResizeObserver` 并清理定时器。

## 4. 全局快捷键可配置（2026-10-25 追加，未发版）

### 4.1 背景

用户：「快捷键的设置要在左侧完整设置面版可调节」——此前全局热键写死在 `MainWindow.xaml.cs` 的静态 `HotkeySpecs`，用户无法查看默认值、无法换键、无法关闭。本轮把热键改为**设置驱动**：完整设置弹窗新增「快捷键」页（查看当前组合/录制换键/开关/恢复默认），宿主按 `settings.shortcuts` 动态注册并持久化。

### 4.2 实现

宿主（`src/Zilux2/`）：

- `Settings/SettingsModel.cs`：新增 `Shortcuts` 段 `{enabled, playPause, prev, next, toggleWindow}`，默认值 `Ctrl+Alt+Space / Ctrl+Alt+Left / Ctrl+Alt+Right / Ctrl+Alt+Z`；`CreateDefaults`/`Clone` 同步。
- `Settings/SettingsService.cs`：读写/Patch/Reset/snapshot 全链路 + `ShortcutsSnapshot`；`internal event Action? ShortcutsChanged`（锁外触发，仅 `shortcuts.*` 或 reset）。
- 新增 `Hotkeys/{HotkeyBinding.cs, HotkeyCatalog.cs, HotkeyState.cs}`：组合键解析（Ctrl/Alt/Shift/Win + A-Z/0-9/F1-F24/Space/Tab/Enter/Esc/Backspace/Delete/Insert/Home/End/PageUp/PageDown/方向键等；至少 1 个修饰键或 F1-F24；规范名 `Ctrl+Alt+Shift+Win+Key`；别名 escape/return/del/ins/pgup/pgdn/arrow*）。

- `ui/app.ts`：`openSettingsSheet` 左侧导航插入「快捷键」（playback 之后）；`buildShortcutsSection()` 渲染启用开关 + 4 行「当前组合胶囊 / 重新录制 / 状态（已生效 / 已回落到 X / 组合被占用 / 未启用 / 未设置）」+「恢复默认组合」；录制用 window capture `keydown`（纯修饰键忽略、Esc 取消、无修饰 Backspace/Delete 清除、合法组合立即 patch）；`sheetScope` 统一退订。

### 4.4 已知限制 / 备注

- 组合键被系统/其它程序占用时：显式设置里若含回退候选则自动回落并在行内提示「已回落到 X」；无法回落时显示「组合被占用，可换一个」。

## 6. BPM 倍速误判修复（p0-3，2026-10-25）

### 6.1 问题

用户反馈「只有晴天对得上，节奏快一点的歌节拍器声音明显慢」——即快歌 BPM 被判成一半、节拍器 click 慢半速。复现：合成 200 BPM 点击轨 → 99.7 BPM；真实快歌 霽れを待つ → 83.7、新宝島 → 78.9（实际约 158–170）。

### 6.2 原因与修复

`src/Zilux2/Analysis/BeatAnalyzer.cs` 的 `EstimateTempo` 用梳状自相关给候选打分（`ac[lag] + 0.5·ac[2lag] + 0.25·ac[3lag]`）。同一段节拍在 bpm 与 2·bpm 上的梳状得分几乎并列，而折叠逻辑只在候选得分 > 1.05× 时才换成 2×，于是快歌常停在半速。

修复：折叠后增加「半拍位置是否有 onset」校验——当 `bpm < 120` 且 `2×bpm` 仍在允许范围时，取 `beatLag = 60·fps/bpm`，比较 `ac[beatLag/2]` 与 `ac[beatLag]`；阈值按区间分档（`bpm < 100` 用 0.55、`100 ≤ bpm < 120` 用 0.78），满足则 `bpm *= 2`。同时把 `AnalyzerVersion` 从 `p0-1` → `p0-2` → `p0-3`（缓存键必须 bump，否则会命中旧分析结果）。

### 6.3 验证

- 合成点击轨 12 条全部正确：75.2 / 89.7 / 110.1 / 119.8 / 128.6 / 151 / 160.8 / 173.1 / 179.3 / 199.3 / 209.1 / 220.2 BPM。
- 真实曲库 corpus（32 条，`research/tmp/beat-corpus.json`）无回归，快歌修正：霽れを待つ **167.4**、新宝島 **157.7**、スペア 178.2；其余不变（晴天系列 124.7–136.8、花海 150.9、House Music 129.6、shuwa 136 等）。

## §12 WSOLA 变速对齐 + 更慢/人声优先的融合（2026-10-25 第十一轮，未发版）

## 16. 尾部渐弱收尾也计入不可听结尾（analyzer p0-5）

### 16.1 背景

用户反馈：「有一些歌曲后面自带渐变变小声，导致还有声音，所以不计入无声位置」——此前 `audibleEndMs` 只排除数字静音（连续 ≥300 ms 低于 -50 dBFS），尾端数字静音不足 300 ms 时直接回退到文件末尾；很多歌结尾是「渐弱到很小声后停止」，这类收尾被当成可听内容，交叉淡化的终点会被拖到文件末尾。

### 16.2 宿主改动

`src/Zilux2/Analysis/TailSilenceDetector.cs`：真静音检测保留；当尾端静音不足 300 ms 时，追加「渐弱收尾」检测：

- 250 ms 能量块 RMS → dB；曲身电平取 80 分位、尾块电平取末 4 块中位数；
- 尾块须低于曲身 ≥8 dB（否则不算渐弱）；
- 从尾部向前用 2 s 滑窗做最小二乘斜率拟合，斜率持续 ≤ -0.7 dB/s 的起点即渐弱开始；
- 校验渐弱段：2–20 s、不超过全曲 40%、整体衰减 ≥8 dB、起点电平不低于曲身 6 dB；
- 通过则 `audibleEndMs = 渐弱开始`，剩余段计入 `tailSilenceMs`；仍保留「至少 10% 时长」下限。

配套：`BeatAnalyzer` 的 `AnalyzerVersion` p0-4 → **p0-5**（缓存键必须 bump，否则命中旧缓存）；`docs/zilux2-beat-analysis-contract.md` §2.1 更新字段语义与检测规则；前端 `web/src/ui/crossfadeDeck.ts` 设置区文案改为「自动跳过曲尾静音与明显渐弱收尾（p0-5 起）」。

## 23. 无缝衔接 auto 过渡时长：从「4 小节夹 5–10 秒」改为自由自适应

### 23.1 背景

用户要求：「这个过渡时长在自动的时候能不能不只是按照当前歌曲的4小节去判断过渡，同时过渡不在局限5-10s，自由变换」。原实现（§11）只按当前歌 4 小节估一个时长再夹到 5–10 秒，慢歌与快歌的实际听感都被这个区间压平，也没有利用到下一首的前奏空间与当前歌的尾奏结构。

### 23.2 实现

全部在 `web/src/ui/crossfadeDeck.ts`：

- 删除 `AUTO_MIN_MS = 5_000` / `AUTO_MAX_MS = 10_000`，auto 只受产品安全上/下限 `MIN_FADE_MS = 1_200` / `MAX_FADE_MS = 32_000` 约束。
- 新增常量：`AUTO_BARS_MID = 6`、`AUTO_BARS_LONG = 8`、`AUTO_SHORT_BAR_MS = 1_300`（`AUTO_BARS = 4`、`AUTO_FALLBACK_MS = 7_000` 保留）。
- 新增/重写一组纯函数（替代原 `resolveFadeLength`）：
  - `beatIntervalOf()` / `barIntervalOf()`：拍间隔优先取分析结果 `beatIntervalMs`，缺失时用 `60_000 / bpm`；一小节 = 拍间隔 × 拍号。
  - `coordinatedBarMs(a, b)`：两首歌 BPM 比在 WSOLA 变速范围（±12%）内 → 用 A 的小节（B 会被拉齐）；拍速差太大 → 取两首小节的谐波平均 `2ab/(a+b)`，让两首都算数。
  - `lastOutroStartMs()`：取分析结果里最后一个 `outro` 段起点，用来判断 A 的尾奏还有多少空间。
  - `buildAutoFadePlan(options, ctx)`：decides 小节数——默认一个乐句 4 小节；小节 <1.3s（≈>185 BPM 或双拍被分析成两倍速）→ 两个乐句 8 小节；B 从第一个强拍到「开始唱词」的前奏空间不足一个乐句 → 按整小节缩短（最少 2 小节，剩余由「整段前奏当过渡」逻辑兜底）；A 尾奏与 B 前奏都 ≥8 小节 → 放宽到 8 小节，一侧 ≥6 小节 → 6 小节（避免在最后的副歌里就开淡）；无拍点回退 `AUTO_FALLBACK_MS = 7s`。目标时长 = 小节数 × 协调小节长，再夹到 1.2–32 秒。
  - `resolveFadePlan()`：手动档位返回固定秒数，auto 走 `buildAutoFadePlan`；`buildSchedule` 在算出 B 的起播点/唱词位置之后调用它（auto 需要前奏空间）。
- 调试快照（`window.__ziluxCrossfade.snapshot()`）新增 `autoFadeMs` / `autoBars` / `autoBarMs` / `autoNote` 四个字段，QA 可直接断言 auto 决策（`autoNote` 取值：两首变速对齐，默认一个乐句 / 两首拍速差较大，取平均小节 / 小节很短，取两个乐句 / B 前奏较短，按整小节缩短 / 一侧空间宽裕，取一个半乐句 / A 尾奏 + B 前奏宽裕，取两个乐句 / 无拍点，回退固定时长）。
- UI 文案同步：auto 按钮 title「自动：按两首歌的拍点/小节与前后奏空间自由决定，不再固定 5–10 秒」；设置项 hint「自动 = 两首歌的拍点/小节 + 前奏尾奏空间自适应，时长自由变化」；功能说明补一段 auto 规则。

## 42. 旋入样式改为「文字随机从各个地方飘进来组成句子」（第三十六轮）

### 42.1 背景（用户要求）

### 42.2 实现

- `web/src/ui/lyrics.ts`：新增稳定伪随机 `scatterHash()`（FNV-1a，按「句内序号 + 整句文字」）与 `scatterRandom()`（按 salt 派生不同维度），`render()` 给每个 `.lyric-char` 写 4 个内联变量：

## 50. 修复歌词页被首页压住：入场动画 fill-mode 覆盖了歌词打开时的隐藏（第四十四轮）

### 50.1 背景

用户 2026-10-26 报障（原话）：「歌词页面展开怎么在页面下方了，自己看」，附截图：打开歌词页后首页（今日推荐 / 私人雷达 / 我的音乐 / 最近播放 / 热门歌单）整层仍显示在歌词页上方，歌词文字与封面在首页卡片的透明缝隙里透出来；播放条、左栏正常。

这是第四十三轮「全面补全交互动画」引入的回归：当时给主视图挂了入场动画，动画的 `fill-mode: both` 把终态 `opacity: 1` 一直填着，压过了歌词页打开时用来隐藏首页的 `opacity: 0`。

### 50.2 实现

- 根因：`app.css` 中 `.app.is-lyrics-open .wall, .app.is-lyrics-open .home-host { opacity: 0; transform: scale(.985) }` 是歌词页显示首页隐藏的正常机制（歌词页 `z-index: 80`，内容层 `.main` 为了保留左栏可点被抬到 `z-index: 81`，所以必须靠隐藏首页来露出歌词页）。第四十三轮追加：
  `.home-host:not(.is-hidden), .wall:not(.is-hidden) { animation: ui-fade-in .22s var(--ease) both; }`
  CSS 动画（尤其 `fill-mode: both/forwards`）在层叠里的优先级高于普通作者声明，于是动画结束后 `.home-host` 的 `opacity` 仍被锁在动画终态 1，`is-lyrics-open` 的 `opacity: 0` 失效；同时 `.main` 背景透明、`pointer-events: none`，所以用户看到的就是「首页浮在歌词页上面、歌词从缝隙里透出来」。
- 修复（`web/src/styles/app.css` 第四十三轮追加段）：
  1. 主视图入场改为只做入场、不锁终态，并限定在未打开歌词时：
     `.app:not(.is-lyrics-open) .home-host:not(.is-hidden), .app:not(.is-lyrics-open) .wall:not(.is-hidden) { animation: ui-fade-in .22s var(--ease) backwards; }`
  2. 同段其它一次性入场动画的 `both` 一并改为 `backwards`（墙头 / 墙面列表 / 首页各块 / 投送设备 / 投送密码与提示条 / 空态 / 点赞弹跳），避免以后再出现「动画终态锁住 opacity/translate、盖掉状态类样式」的同类问题。
- 结论：一次性入场动画不要用 `both`；除非确实需要动画结束后继续锁住某个值，否则 `backwards` 更安全（动画期间保持首帧、结束后释放属性）。

## 53. 歌词衔接二轮：人声缓慢浮现 + 人声聚焦分离伴奏（第四十七轮）

### 53.1 背景

- `applyEqualPowerGains` 的 handoff 分支给 B 用了 `0.58 + 0.42·sin(…)`，并在 90 ms 内起音到 58% —— 人声是「硬切」进来的，听感突然。

### 53.2 实现

- `web/src/core/audioTap.ts`（621 行）：deck 图节点增加 `presence`（peaking、1800 Hz、Q 0.9、gain 0），链路改为 source → low → high → presence → gain；新增 `setDeckGraphVocalFocus(element, amount)`：低频 -15 dB、高频 -11 dB、1.8 kHz 临场感 +4.5 dB（按 amount 线性）；`detachDeckFromGraph` 复位 presence。
- `web/src/ui/crossfadeDeck.ts`（1678 行）：handoff 曲线重写——

  - B 的前几秒「人声聚焦」：`focus = 1 - smoothStep(min(1, elapsed/openMs))`、`openMs = clamp(fadeMs*0.45, 1200, 4200)`，逐帧 `setDeckGraphVocalFocus(standby, focus)`，A 侧同时用 tilt 压伴奏；非图模式只用增益。
  - `startFade` 时 handoff 预置 B 的 vocalFocus=1、tilt 归零；`startManualFade` / `failManualFade` / `finishFade` / `hardCutToStandby` / `cancelCrossfade` 全部复位 vocalFocus=0，避免残留 EQ。
  - 文件头注释、设置说明、日志文案、开关 toast、设置页大段说明同步改为「人声缓慢浮现、人声聚焦分离伴奏」。

## 55. 歌词衔接过渡时长封顶 8 秒 + 尾奏较多时先保留一点尾奏（第四十九轮）

### 55.1 背景

> 目前测试出一个问题，就是衔接的时候最后一句话唱完后衔接到下一首句的时候渐变过渡会把上一首整段尾部无词继续当作过渡时间，这样导致的过渡时间过长

第一件事：第三轮（§51）的歌词衔接把淡化窗口的终点固定成「可听结尾」，起点 = 可听结尾 − 尾奏长；于是 A 末句唱完后整段无词尾奏都被算进过渡，最长 32 秒，实测 9 秒以上。

- 新增 `HANDOFF_MAX_FADE_MS = 8_000`（歌词衔接的过渡时长上限，不把整段无词尾奏当过渡）；

- 新增「先保留尾奏」判断：`HANDOFF_HOLD_MAX_MS = 6_000`、`HANDOFF_HOLD_RATIO = 0.5`，`handoffHoldMs = round(min(HANDOFF_HOLD_MAX_MS, max(0, tailAfterVocalMs - handoffFadeMs) * HANDOFF_HOLD_RATIO))`——只把「尾奏减去过渡时长」的剩余部分分一半（最多 6 秒）留给 A 先播，再去交接，保证淡化仍在可听结尾之前结束；

## 56. 歌词衔接四轮：去掉固定封顶，过渡时长按真实小节纯计算（第五十轮）

### 56.1 背景

2026-10-27 用户反馈（原文）：**「能不能不设置封顶，纯计算，在完美过渡自动选取适合时间」**。

第四十九轮为了不让过渡过长，给歌词衔接加过固定上限（过渡封顶 8 秒、保留尾奏封顶 6 秒）。固定秒数对不同歌曲不够自然：慢歌一个乐句可能就十几秒，快歌一个乐句只有几秒。本轮把固定封顶全部去掉，改由两首歌的真实小节与尾奏长度算出一个「音乐上合适」的交接窗口。

### 56.2 实现

`web/src/ui/crossfadeDeck.ts`：

- 删除 `HANDOFF_MAX_FADE_MS = 8000`、`HANDOFF_HOLD_MAX_MS = 6000`、`HANDOFF_HOLD_RATIO = 0.5`，改为按小节计算：
  - 小节 = `coordinatedBarMs(A, B)`（B 在过渡期间会被 WSOLA 拉齐，所以用协调小节；没有拍点分析时回退 `HANDOFF_FALLBACK_BAR_MS = 2000` 估算）；
  - 一个乐句 = 4 小节；小节短于 `AUTO_SHORT_BAR_MS`（1.3 秒）时取两个乐句（8 小节），与普通自动淡化一致；
  - 尾奏 > 一个乐句：多出来的部分按整小节留给 A 独听（`handoffHoldMs = floor((尾奏 − 乐句) / 小节) × 小节`），交接点自然往后，保留听感；
  - 剩余尾奏 = 交叠时长，交叠终点正好落在 A 的可听结尾——A 的尾奏既不会被截断，也不会把整段尾奏拖成交叠；
  - 尾奏 ≤ 一个乐句：整段尾奏都用来交叠（hold = 0，末句唱完立刻开始）；
  - B 后半段撑不到交叠结束：把交叠缩短（hold 相应变大），仍不足 `MIN_FADE_MS` 回退普通淡化；
  - 尾奏不足 `MIN_FADE_MS`（1.2 秒）仍按原逻辑回退普通淡化。
- `autoNote`、准备日志与设置页文案同步：不再出现「封顶 8 秒 / 最多保留 6 秒」，改为说明按小节计算、尾奏多时先独听整小节尾奏。

## 57. 单实例运行 + 禁用双指缩放（第五十一轮）

### 57.1 背景

用户 2026-10-27 反馈（原话）：「同时把软件可以同时打开多个的问题解决掉，同时在app的时候双指放大的也禁用掉」。

- 第二个问题：重复双击启动图标 / 从开始菜单和托盘同时点，会起多个 Zilux2 进程——多个窗口、多个托盘图标、多套全局热键互相抢占，播放状态也各自为政。
- 另一个问题：播放页是 WebView2，触摸板 / 触屏的双指捏合（以及 Ctrl+滚轮）会把整个界面缩放，而 WebView2 会按站点记住缩放比例，误触后界面回不来。

### 57.2 实现

- **单实例（宿主 `App.xaml.cs`）**：
  - 用命名互斥体 `Local\Zilux2.SingleInstance` 判定谁先启动；第二个进程向 `Local\Zilux2.Activate` 自动重置事件发信号后立即 `Shutdown(0)`，不再创建窗口 / 托盘 / 热键。
  - 主实例在后台线程 `Zilux2-Activate` 等待信号，收到后经 UI Dispatcher 唤出窗口：已隐藏到托盘 → `ShowFromTray()`（日志 `tray.show`），否则 `Activate()` + `SetForegroundWindow`（日志 `instance.focus`），并记录 `instance.show`。
  - 检查放在 `AccountSelfCheck` / `AirPlayLoopbackTest` 自测分支之后——工具的自测进程需要在应用已运行时也能跑。
  - 互斥体 / 事件创建异常只记 `host.instance check failed` 并照常启动（单实例只是体验保护，不能挡住播放）；退出时释放句柄。
  - 跨线程修正：等待线程不能直接访问 `Application.MainWindow`（会抛「该线程无法访问此对象」），改为主线程 `OnStartup` 捕获 `Dispatcher`，等待线程只 `Dispatcher.BeginInvoke`，在 UI 线程里再取窗口调用 `MainWindow.ActivateFromSecondInstance()`。
- **禁用缩放（宿主 `WebViewHost.cs`）**：`InitializeAsync` 里 `core.Settings.IsPinchZoomEnabled = false`、`core.Settings.IsZoomControlEnabled = false`、`_webView.ZoomFactor = 1.0`，日志 `webview2 zoom disabled pinch=False control=False factor=1.00`。
