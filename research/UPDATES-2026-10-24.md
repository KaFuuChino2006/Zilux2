## 1. 房间效果：粒子 / 流星快捷预设（新功能）

快捷设置 →「歌词」tab →「房间设置」面板里，为「粒子」和「流星」两组各加一行预设 chips，一键切换风格；数值仍可继续拖滑杆微调，保存后写入 `zilux2.roomStyle`，取消/关闭会还原。

- 粒子预设（count, size, brightness, speed, drift）：
  - 星尘 stardust `36, 1, 1, 1, 1`（默认，初始高亮）
  - 萤火 firefly `64, 1.3, 1.2, 0.55, 1.6`（更多更亮、慢慢飘）
  - 雪点 snow `72, 0.55, 1.9, 0.4, 2.2`（小而亮、冷白、漂移大）
  - 静谧 hush `12, 2.2, 0.45, 0.3, 0.6`（极少、大而暗、几乎不动）
- 流星预设（strength, count, speed, length, width）：
  - 默认 default `1, 7, 1, 0.28, 1`（初始高亮）
  - 流星雨 rain `0.85, 12, 2.2, 0.2, 0.55`（多而快、细）
  - 彗星 comet `1, 3, 0.75, 0.72, 1.6`（少而长拖尾）
  - 微光 glow `0.4, 5, 0.25, 0.5, 1.8`（缓慢、偏暗、尾巴粗）
- 实现：`web/src/ui/roomSettings.ts` 新增 `PARTICLE_PRESETS` / `STREAK_PRESETS` / `applyRoomEffectPreset` / `roomEffectPresetMatches`；`roomSettingsPanel.ts` 渲染两行 chips（`.room-preset-row`，按钮 `.room-preset-chip[data-preset-kind][data-preset-id]`，匹配值加 `is-active`）；新样式 `web/src/styles/room-presets.css`。
- 细节：点 chip 只改面板 draft（立即预览），必须点保存才落盘；粒子 count=0 时点预设自动兜底为 8；点「恢复默认」会重新高亮默认项。不改 `app.css`，不新增依赖。

## 2. 本地音乐目录自动监控（新功能）

设置本地音乐文件夹后，宿主用 `FileSystemWatcher` 递归监听该目录；新增/修改/删除/重命名音频/歌词文件会自动刷新本地曲库（页面收到 `localLibrary` 事件自动重渲染），不用再手动点刷新。

- 新增 `src/Zilux2/Local/LocalFolderWatcher.cs`（约 560 行）：递归监听、InternalBufferSize 64KB、1300ms 静默去抖（单 Timer）、错误退避重启（2s 起、最长 30s）、`Start/Stop/Dispose` 幂等。
- 新增 `src/Zilux2/Local/LocalMusicService.Watch.cs`（partial，约 750 行）：
  - 生命周期：`Load()` 成功启动监听（先启动 watcher 再扫描）、切换文件夹时先停旧 watcher、失败/目录不存在时停掉并记日志、`Dispose()` 释放。
  - 事件处理：忽略 `~$`/`.tmp`/`.part`/`.crdownload` 等临时文件与隐藏文件；文件级变化走**增量单文件重扫**（只解析变化文件，UI 内存列表 diff 后只推变化项），批量/结构性变化（>30 项、重命名、目录变化）走一次整目录重扫。
  - 线程安全：事件在线程池线程，所有 `_post`/UI 交互经 `Dispatcher` 切回 UI 线程；`NotifyFileAdded`（下载完成）同样修正了跨线程问题。
  - 自写入抑制：宿主自己下载落地/删除文件时 15s 内不重复触发扫描（避免与 `NotifyFileAdded` 重复刷新）。
  - 日志：`[local] watch started: <dir>` / `watch stopped` / `watch event batch: N` / `watch incremental: +a -b` / `watch rescan` / `watch error`。
- 顺带修复（宿主）：`LocalMusicService.DeleteTracks` 删除文件后没有抑制自身写入 → 会被 watcher 再触发一次重扫；现在会先 `MarkHostWrite`。
- 已知限制：网络盘/超大目录只保证不崩，实时性取决于系统事件；监控不提供设置开关（默认开启）。

## 3. 下载队列面板（新功能）

播放条右侧新增下载入口按钮（`[data-qa="download-entry"]`，有进行中任务时显示数量徽标）；点开「下载队列」浮层：

- 汇总：`N 进行中 / M 已完成 / K 失败`；筛选 tab：全部 / 下载中 / 已完成 / 失败。
- 每行：歌名 + 歌手·品质、进度百分比 + 进度条（total 未知时 indeterminate）、速度（MB/s，两次采样差值计算）、状态文案；已完成行显示「在文件夹中显示」（调 `/api/download/reveal`）；失败行显示「重试」（按 source/trackId/title/artist 重新入队）；面板底部显示下载目录 +「打开目录」。
- 空状态、加载/失败错误条；列表来自宿主 `GET /api/downloads`（本进程会话内最多 30 条），面板关闭不丢状态、页面切换不重建。
- 轮询策略：有进行中任务 1.2s 刷新，无任务降频/暂停，页面隐藏时 5s；行级 diff 更新不整表重建；`app` dispose 时清理定时器与 DOM。
- 实现：新增 `web/src/ui/downloadQueue.ts`（约 897 行）+ `web/src/styles/download-queue.css`（约 488 行，由 TS 引入，不改 `app.css`）；`web/src/ui/app.ts` 仅最小接线（入口、`beginDownload` → `beginQueueDownload`、dispose）。旧 `watchDownload` 1200ms×160 的单任务轮询删除。
- 已知限制：宿主暂未提供「取消 / 清空队列」接口，面板不伪造这些能力（底部有提示）。
